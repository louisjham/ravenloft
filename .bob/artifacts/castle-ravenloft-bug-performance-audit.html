🔴 Critical Bugs

Critical Duplicate card handlers — dead code in EncounterSystem

src/game/engine/EncounterSystem.ts · Lines 526 and 1102 (Cyrus Belview) · Lines 788 and 1148 (Strahd's Whispers)

Both 'enc_cyrus_belview' and 'enc_strahds_whispers' have two separate if (card.id === ...) handlers inside the same resolution function. Because the first match hits a return, the second handler (at lines 1102 and 1148) is unreachable dead code. The second implementations are actually different from the first — the Cyrus Belview second pass picks a random unexplored edge instead of always points[0], and the Strahd's Whispers second pass uses a deferred power-select flow. The intended behavior is silently discarded every time these cards are drawn.

Critical Missing hasAttackedThisTurn reset in cancelEncounterWithDispelMagic

src/store/slices/cardSlice.ts · Lines 277–280 vs. dismissCardResolution at Line 479

The cancelEncounterWithDispelMagic path that handles a pendingEncounter resets per-turn hero flags (extraActionsThisTurn: 0) but does not reset hasAttackedThisTurn. The sibling function dismissCardResolution correctly resets it at line 479. This means a hero can gain a free second attack after dispelling an encounter card in the same turn.

🟠 High Issues

High Multiple set() calls in endTurn — up to 4 commits per turn

src/store/slices/coreSlice.ts · Lines 295–571

endTurn uses an intermediate let s = { ...state } correctly for most of its logic, but then early-returns with separate set() calls at lines 471 (defeat), 475 (victory), 481 (coffin victory), 497–515 (encounter draw), and 530 (defeat at next-turn start). Each early return triggers a full React reconciliation and re-render of every subscriber before the flow is complete. Unifying all paths to a single set() at the end with a computed nextPhase would eliminate the extra renders.

High Two separate set() calls in cancelEncounterWithDispelMagic

src/store/slices/cardSlice.ts · Lines 199–301

The if (pendingEncounter) branch calls set() at line 242–282 and the else branch calls set() again at line 299. Both paths should build a new state object and commit it in a single set() call to avoid two reconciliation cycles.

High Unguarded production console.log / console.error in engine and store

CombatSystem.ts:87 · ActionResolver.ts:19 · PowerSystem.ts:169 · ConditionSystem.ts:82, 96, 110 · EncounterSystem.ts:2212, 2222 · coreSlice.ts:46, 59, 583, 611, 651, 659 · powerSlice.ts:143, 206 · TileSystem.ts:172, 179, 196, 277, 283, 290, 307 · ExperienceSystem.ts:48 · MonsterAI.ts:195, 422, 1029

Dozens of console.log, console.warn, and console.error statements fire in production builds because they lack an isDev() guard. Notably: CombatSystem.ts:87 fires on every Bat Swarm roll; ActionResolver.ts:19 fires on every movement check for an immobilised hero; PowerSystem.ts:169 fires on every power card play with the Cackling Skull environment; ConditionSystem.ts:82/96/110 fire every turn-end for every entity with conditions; TileSystem warns on every failed tile draw.

High Broad gameState subscription in useExplorationControls defeats memoisation

src/hooks/useExplorationControls.ts · Line 16

const gameState = useGameStore((state) => state.gameState) subscribes to the entire game state object, so the hook re-renders on every state change anywhere in the game. All three useCallbacks include gameState in their dependency arrays, meaning they are recreated on every re-render, defeating memoisation entirely. The hook only needs phase, hasExploredThisTurn, and tiles.

High Heavy per-frame work in Hero3D useFrame loop

src/components/3d/Hero3D.tsx · Lines 130–223

The useFrame callback performs on every frame: world/local matrix updates, a gameState query + full monster array traversal to find threat targets, continuous sin()-based material mutations, and a traverse() call over the entire model graph with per-mesh material mutations. At 60 fps this is ~3600 monster-array scans per minute per hero instance. Threat target selection should be derived once outside the frame loop and passed as a prop, with the frame loop responsible only for interpolation toward that already-computed target.

High Handler functions not memoised with useCallback in useGameActions

src/hooks/useGameActions.ts · Lines 24, 176, 200, 237, 244, 296, 316

All primary handler functions (handleMoveHero, handleAttackMonster, handleEndTurn, handleSelectEntity, handleSearchToken, getSearchableTokens, canSearch) are recreated on every render. Components that receive these as props will see new references every render, negating any React.memo on those components.

High Incomplete implementation — discardTreasureForPower is a stub

src/store/slices/coreSlice.ts · Lines 650–653

The action body is: console.log('discardTreasureForPower called for', heroId); // TODO: implement. Any call site that relies on this action silently does nothing, and the unguarded console.log fires in production.

🟡 Medium Issues

Medium Null dereference risk on targetTile in TreasureSystem

src/game/engine/TreasureSystem.ts · Line 1048

const targetTile = base.tiles.find(...) can return undefined, but the result is immediately used as targetTile.x and targetTile.z without a null check. A missing tile ID in the fortune choice will throw a runtime TypeError.

Medium Inconsistent cardId: '' vs cardId: null in idle card resolution state

src/store/slices/cardSlice.ts · Line 290 vs Lines 437, 494

The cancelEncounterWithDispelMagic else-branch sets cardId: '' for the idle card resolution reset, while dismissCardResolution and other idle resets use cardId: null. Consumers that check if (!cardResolution.cardId) will behave differently depending on which code path was taken.

Medium Unsafe as Hero cast without type guard in CombatSystem

src/game/engine/CombatSystem.ts · Line 306

const heroAttacker = attacker as Hero is performed before any type check, so if a monster is passed as attacker in a future call path, hero-specific property accesses will silently return undefined rather than throwing early. A discriminated union check on attacker.type === 'hero' should precede the cast.

Medium Multiple as any casts hiding type errors in store and engine

coreSlice.ts:514, 530, 569 · TreasureSystem.ts:1048, 1085, 1472 · CardResolutionSystem.ts:41, 43

Several state objects are cast to any before being passed to set() or stored. This bypasses TypeScript's structural checking at the most important boundaries and can mask missing required properties on GameState.

Medium Per-frame monster array traversal in Dice3D even when dice are hidden

src/components/3d/Dice3D.tsx · Lines 20–25

The activeHeroPos selector performs a deep gameState traversal on every render, and its result — a new object — is used as the useMemo dependency at line 27, causing the arena position to be recomputed on every render rather than only when the hero position changes. The selector should return a stable primitive pair (e.g. [x, z]) or be skipped entirely when phase !== 'rolling'.

Medium React.memo protection bypassed on Tile3D and Hero3D

src/components/3d/Tile3D.tsx · Line 283 · src/components/3d/Hero3D.tsx · Line 457

Both components are wrapped with React.memo, but their parents pass callbacks (onMoveHero, event handlers) that are not wrapped in useCallback. Every parent render produces new function references, causing memo to always consider props changed and re-render all tile and hero instances.

Medium Stale monster reference after state mutation in villain phase

src/store/slices/villainPhaseLogic.ts · Line 74 vs. Line 116

The variable monster is fetched from newState at the top of the loop, then newState is mutated (monster HP, position) by helper calls before monster is referenced again at line 116. Some paths defensively refetch (newState.monsters.find(...) at line 227), but the top-level loop does not, creating a window where stale data drives movement/attack decisions.

Medium O(n²) Array.includes inside villain queue construction loop

src/store/slices/villainPhaseLogic.ts · Lines 43, 52

The queue is built by calling !queue.includes(monster.id) inside a loop over all monsters. With n monsters the inner check is O(n) giving O(n²) overall. At typical counts this is harmless but degrades as encounters stack monsters; replacing queue with a Set makes it O(n).

Medium useFrame on MovementSquare3D runs every frame with no throttle

src/components/3d/Tile3D.tsx · Lines 217–227

Every visible movement square runs a continuous scale animation that reads clock.getElapsedTime() and mutates the mesh scale 60 times per second. With 16 squares per tile and multiple revealed tiles this scales badly. Since the animation is purely visual (a slow pulse), the scale update could be driven by a shared clock value computed once per frame at a parent level and passed down, or the component could share a single AnimationMixer.

Medium Non-null assertion without prior guard in useExplorationControls

src/hooks/useExplorationControls.ts · Line 97 (handlePlacementConfirm)

Inside handlePlacementConfirm, const pt = gameState.tiles.find(...) returns undefined if the tile is missing, but the result is immediately used without a null check. This would throw a TypeError in any edge case where the referenced tile has been removed from state before the placement is confirmed.

⚪ Low / Code Smell

Low Duplicate hero turn-reset literal in three locations

cardSlice.ts:277–280 · cardSlice.ts:479–486 · coreSlice.ts:545–568

The pattern of resetting extraActionsThisTurn: 0, hasRolledNatural20ThisTurn: false, etc. is copy-pasted in three places. One authoritative resetHeroTurnState(h: Hero): Hero utility would prevent future drift (and is what allowed the hasAttackedThisTurn omission to go unnoticed).

Low Biased shuffle — .sort(() => Math.random() - 0.5)

src/store/slices/coreSlice.ts · Line 115 (and other deck-shuffle sites)

Sorting with a random comparator is not a uniform shuffle — it produces a statistically biased ordering because the sort algorithm makes assumptions that are violated by non-deterministic comparators. A standard Fisher-Yates in-place shuffle should be used instead, and the project already has one written in some paths — it should be extracted as a shared utility.

Low Hardcoded scenario and card ID string literals scattered across slices

coreSlice.ts · cardSlice.ts · EncounterSystem.ts

Strings like 'adventure_tome_of_strahd', 'enc_cackling_skull', 'rogue_spring_away', 'wizard_dispel_magic' appear in multiple files without being imported from a constants module. A typo in any one of them silently breaks the affected card's behaviour.

Low Inline array literal ['north','south','east','west'] allocated each render in Tile3D

src/components/3d/Tile3D.tsx · Line 190

A new array is created on every render. It should be a const declared outside the component.

Low Inline material objects created on every render in Hero3D

src/components/3d/Hero3D.tsx · Lines 316, 337–342, 345–348, 356–357, 366–372

orbColor, outline material color, and emissive values are computed inline on every render. These should be wrapped in useMemo or useCallback with appropriate dependencies to prevent Three.js from regenerating GPU material descriptors on each React reconciliation.

Low Inconsistent log-counter increment pattern in villainPhaseLogic

src/store/slices/villainPhaseLogic.ts · Lines 91, 97 vs. 495

Some sections use the clean let counter = newState.logIdCounter ?? 0; counter++ idiom; others repeat the verbose String((newState.logIdCounter ?? 0) + 1) expression inline, which doesn't increment the stored counter. The inconsistency means log IDs from different code paths may collide.

Low CardSystem class is unused

src/game/engine/CardSystem.ts · Line 6

A comment at the top of the file states the class is "currently unused since all slices manage decks directly." The file should either be removed or the responsibility it was intended to own should be formally assigned to it.

Low Inline dynamic import for ConditionType in TreasureSystem

src/game/engine/TreasureSystem.ts · Lines 846, 964

import('../types').ConditionType is used as an inline type reference instead of a top-level import. This is a code smell and may confuse bundlers or type checkers.

Low ExplorationLayer — pure helper function defined inside component

src/components/3d/ExplorationLayer.tsx · Lines 43–52

isHeroAtEdgeFor() is a pure calculation that depends only on its arguments but is redefined on every render. Moving it outside the component (or to a shared utility) removes the allocation and keeps the component body focused on rendering logic.
